# File structure

Three products and the API they share. Read it with `SETUP.md` (downloads, keys, run commands).

Everything in the tree exists now as a stub with a one-line comment saying what it will do. There is no feature logic yet. The only real code is the Makati pin (`config/`), the map style URLs, the env readers and the server's `/health` route. Entries marked "generated" are created by Vite or Flutter in SETUP step 5.

## How the structure keeps things toggleable

1. **One registry per app.** `layers/registry.ts` (`layer_registry.dart` on mobile) lists every layer once: id, label, group, default on or off. `LayerPanel`, `FloatingToolbar` and the mobile `layer_sheet` all render from it. A layer is one file plus one registry line.
2. **Panels are independent.** `Sidebar`, `ListPanel`, `DetailPanel` and `Legend` each open and close on their own. `store/ui.ts` remembers which are open.
3. **Switch state is remembered.** `store/layers.ts` (`layers_state.dart` on mobile) keeps which layers are on, so a refresh does not reset the screen.
4. **Lenses are presets.** In `open-dashboard`, Commuter and Business are each a `preset.ts` that sets which layers and panels start on. Switching lens flips the switches. The user can still change any of them.
5. **Makati is pinned in one place per app.** `config/makati.ts` in the dashboards, `config/makati.dart` in the app. The numbers are approximate, so tune them once on screen. The server's side of the pin is `OSM_PLACE` in `server/.env`.

## Two dashboards, one skeleton

`lgu-dashboard` and `open-dashboard` have the same folders on purpose. Build the map shell (`map/`, `layers/`, `toolbar/`, `panels/`, `store/`) in one, then copy those folders across. If the two copies start to drift, move them into a shared package later. It is not worth doing in the first 24 hours.

## The fourth folder

You asked for three root folders. `server/` is the fourth because all three apps call the same API, as in the plan. To keep strictly three, move it into `lgu-dashboard/`, but the open dashboard and the app would then depend on a folder that belongs to another product.
